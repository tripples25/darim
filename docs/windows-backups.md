# Зашифрованные резервные копии Windows

Утилита хранит архивы в `%USERPROFILE%\.codex\darim-backups`. Windows получает
архив через SSH-профиль `darim-prod` и явно заданный UUID сервиса Darim;
содержимое stdout передаётся напрямую шифратору, а на диск попадает только AES-256-зашифрованный архив. Локальная
копия ключа защищена DPAPI текущего пользователя. Папка архива получает ACL
только для этого пользователя.

## Команды

```powershell
./ops/windows-backup/darim-backup.ps1 -Action Backup
./ops/windows-backup/darim-backup.ps1 -Action Status
./ops/windows-backup/darim-backup.ps1 -Action Verify -BackupPath "$env:USERPROFILE/.codex/darim-backups/darim-....darim"
```

`Backup` получает дамп PostgreSQL, файлы ключей ASP.NET Data Protection,
сгенерированный Coolify Compose и окружение запущенных контейнеров Darim.
Удалённая сторона создаёт временные файлы с закрытыми правами и удаляет их при
завершении. Экспорт прерывается, если выполняется выкладка, база не здорова,
невозможно однозначно определить текущие контейнеры или архив превышает 32
MiB. Дамп и секреты на Windows не сохраняются в открытом виде.

`Status` показывает только время последней успешной копии и её возраст.
После успешной копии удаляются только просроченные архивы, которые проходят
проверку DPAPI и HMAC; произвольные файлы и неподтверждённые архивы не удаляются.
Срок хранения по умолчанию — 30 дней.

Дополнительный переносимый ключ создаётся только по отдельной команде. Пароль
вводится дважды в скрытом приглашении и должен содержать не менее 12 символов:

```powershell
./ops/windows-backup/darim-backup.ps1 -Action ExportRecoveryKey `
  -BackupPath "$env:USERPROFILE/.codex/darim-backups/darim-....darim" `
  -Destination "E:/darim-recovery.recovery"
```

Recovery-файл зашифрован отдельным ключом PBKDF2-HMAC-SHA256 и защищён HMAC.
Сохраните его отдельно от компьютера и запомните пароль. Без него потеря
Windows-профиля лишает доступа к DPAPI-ключам архивов.

Удалённый экспорт обращается только к сервису с настроенным UUID и проверяет
UUID Compose-проекта, образ приложения, здоровую БД, том `darim_postgres` в
`/var/lib/postgresql` и том `darim_keys` в `/keys`. Перед отправкой архив PostgreSQL проверяется
командой `pg_restore --list`. Экспорт прекращается при занятом блокировочном
файле выкладки.

## Периодический запуск

Встроенный `InstallSchedule` создаёт задачу для текущего интерактивного
пользователя: запуск при входе и ежедневно, с `StartWhenAvailable`. Задача
пропускает параллельный запуск и не выполняется как SYSTEM. Она не была
зарегистрирована при разработке; регистрацию следует выполнять только после
проверки этого изменения родителем.

Windows может быть выключена или пользователь может не войти в систему, поэтому
копия обновляется только при доступности компьютера и SSH. Это не обеспечивает
гарантированный RPO 24 часа. Архивы остаются на одном Windows-компьютере; без
отдельной копии потеря этого устройства может уничтожить резервирование.

Этот workflow пока не выполняет restore drill. До отдельной проверки
восстановления он не доказывает RPO/RTO и не должен считаться проверенным
аварийным восстановлением.
