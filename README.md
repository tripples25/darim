# Дарим 🎁

Общий вишлист закрытой компании: один список по людям, скрытая бронь и совместные подарки с равными долями. Обычный сайт и Telegram Mini App используют один Blazor WebAssembly интерфейс и ASP.NET Core API.

**Стек:** .NET 10 LTS, Blazor WebAssembly, MudBlazor, PostgreSQL 18, EF Core/Npgsql, Docker Compose, Caddy.

## Локальный запуск

Нужны .NET SDK из `global.json`, Docker с Compose. Node нужен только для браузерных тестов.

```sh
docker compose -f compose.dev.yaml up -d --wait
dotnet restore --locked-mode
dotnet run --project src/Wishlist.Server
```

Открыть **http://127.0.0.1:5080**. В Development включены четыре демонстрационных аккаунта и примеры желаний. Вход кнопками «Юлия», «Макс», «Аня», «Саша» позволяет проверить брони с разных браузерных профилей. Development автоматически применяет миграции и заполняет пустую базу. Для реальной авторизации нужны настройки ниже; демонстрационные аккаунты не предназначены для публикации.

В Production демонстрационный вход не регистрируется, даже если `Demo__Enabled=true`. Пароль и ключ из `appsettings.Development.json` используются исключительно локально. Сервер без production-подключения к базе и ключа подписи откажется запускаться.

## Возможности

- Общий список, свои желания, «Я дарю», поиск, фильтры по человеку, празднику, цене и доступности, архив.
- Один праздник на желание, включая свой повод; дата и цена необязательны. Цены в рублях, переводы вне приложения.
- Индивидуальная бронь либо распил: координатор выбирает число долей и занимает первую; человек занимает одну долю. Для распила нужен контакт, минимум два дарителя и получатель.
- Передача координации, выход, отмена, отметка покупки. После покупки отмена и выход блокируются. Получатель архивирует полученное желание.
- История исходного желания для дарителей и уведомления об изменениях, выходах, передаче координации и архивации.
- Создание компании, приглашения с возможностью перевыпуска, профиль. В первой версии один аккаунт состоит в одной компании.

Приглашение может быть одноразовым, на выбранное число вступлений (от 1 до 100) или без ограничения. Начальная ссылка при создании компании одноразовая. Сайт и Telegram используют один общий лимит. Учитываются только новые вступления; повторный переход участника не расходует лимит. Перевыпуск отключает предыдущую ссылку, действующие участники остаются в компании. Старые ссылки, созданные до появления лимитов, остаются неограниченными до перевыпуска.

Лимит не проверяет личность: если переслать ссылку, первым её может использовать любой получатель. Для одного человека безопаснее отправить отдельную одноразовую ссылку и убедиться, что вступил именно он.

## Приватность и конкурентные изменения

Получателю сервер возвращает `participation: null` и `original: null`, включая архив, а не скрывает статус средствами CSS. Индивидуальный даритель не раскрывается другим участникам. Имена и контакты участников распила доступны только внутри этого распила. Публичные карточки и список участников компании не раскрывают контакт профиля. У организатора нет отдельного доступа к скрытым броням.

Все изменения карточки блокируют одну и ту же строку `Gifts` через `SELECT ... FOR UPDATE` в транзакции. Доли загружаются после получения блокировки. Уникальный ключ `(GiftId, UserId)` запрещает вторую долю; конфликтующие действия возвращают HTTP 409. Защита от дублей относится к одной карточке: одинаковые желания, введённые отдельно, не распознаются автоматически.

## Настройка Telegram

1. Создать бота через **@BotFather**. Сохранить токен в `TELEGRAM_BOT_TOKEN`, имя без `@` — в `TELEGRAM_BOT_USERNAME`.
2. Указать HTTPS-адрес приложения как **Main Mini App** и кнопку меню бота. Telegram передаёт `initData`; сервер проверяет HMAC, дату (не старше 5 минут, допуск будущего 30 секунд), обязательные поля и отсутствие дубликатов. `initDataUnsafe` используется только как подсказка навигации, никогда для авторизации.
3. В настройках Telegram Login зарегистрировать origin `https://ВАШ-ДОМЕН` и callback `https://ВАШ-ДОМЕН/auth/callback`. Полученные Client ID/Secret указать в `TELEGRAM_CLIENT_ID` и `TELEGRAM_CLIENT_SECRET`.
4. В браузере используется OIDC Authorization Code + PKCE с серверной проверкой токена и cookie-сессией. В Mini App — отдельный bearer-токен на час, хранящийся только в памяти. После истечения Mini App нужно открыть заново. Оба входа привязаны к Telegram ID.
5. Приглашения доступны как обычные ссылки `/?invite=...` и `https://t.me/BOT?startapp=join_...`. Перевыпуск приглашения отключает старую ссылку.

Документация: [Mini Apps](https://core.telegram.org/bots/webapps), [Telegram Login / OIDC](https://core.telegram.org/bots/telegram-login).

Тема Telegram, safe area, кнопка «Назад» и ссылки поддерживаются через небольшой JS interop адаптер. Реальный вход, виджет клиента и поведение WebView необходимо проверить с вашим ботом на Android, iOS и Desktop. Автоматические проверки используют подписанные тестовые данные; они не заменяют проверку настоящих клиентов. Сообщения от бота не отправляются.

## Подключение Ohmywishes

1. Получить у команды Ohmywishes реквизиты OAuth-клиента для [MCP](https://support.ohmywishes.com/ru/knowledge-base/mcp/). Подтвердить право чтения вишлиста, выдачу refresh token, лимиты фоновых запросов и показ карточек в закрытой компании. Зарегистрировать HTTPS callback `https://ВАШ-ДОМЕН/auth/ohmywishes/callback`.
2. Заполнить `OHMYWISHES_*` из `.env.example` значениями провайдера и применить миграции при развёртывании. Приложение запрашивает `wishlist:read`. Поддерживаемые способы аутентификации токен-эндпоинта — `client_secret_basic`, `client_secret_post`, `none`. Начальный интервал обновления — 30 минут. Для расшифровки сохранённых токенов нужен тот же volume `keys`.
3. В браузере войти в «Дарим», открыть профиль, подключить Ohmywishes и выбрать список. Карточки появятся в общем списке компании. Из Telegram Mini App можно перейти в браузер для подключения, затем выбрать список или отключить интеграцию в любом из двух интерфейсов.

Импорт охватывает общедоступные желания и желания, доступные по ссылке, из выбранного списка. Бронь и распил работают внутри «Дарим». В пилоте бронируйте импортированные желания в одном сервисе, чтобы избежать двойной покупки.

### Закрытый пилот через веб-API

Для пилота укажите Telegram ID одного участника в `OHMYWISHES_WEB_API_TELEGRAM_ID` и задайте `OHMYWISHES_WEB_API_ENABLED=true` в окружении приложения. По умолчанию пилот выключен. В профиле этого участника появится поле для ссылки на отдельный публичный список вида `https://ohmywishes.com/users/имя/lists/идентификатор`. Участник подключает собственный список. Импорт читает опубликованные карточки анонимными GET-запросами, а бронь и распил хранятся в «Дарим». При отключении флага карточки пилота скрываются, а опрос прекращается.

Перед откатом на версию без интеграции остановить приложение и откатить миграции `OhmywishesWebPilot` и `OhmywishesSync`. Откат удаляет подключения и скрытые импортированные карточки. Видимые карточки MCP сохраняются как обычные желания.

## Развёртывание на VPS

Автоматические тесты, сборка Docker-образа и ручной деплой выполняются в
[Woodpecker CI](https://ci.hype-ny.ru/repos/1): [настройка и запуск](docs/woodpecker.md).
GitHub Actions workflow сохранён как альтернативный вариант, но отключён.

Ориентир: Linux, 2 vCPU, 4 ГБ RAM, 40 ГБ SSD, Docker Compose. Windows/IIS не нужны. Разместить проект, например, в `/opt/darim`.

1. Направить DNS домена на VPS. Открыть TCP 80/443 и SSH. База и ASP.NET Core не публикуют порты наружу.
2. Скопировать `.env.example` в `.env`. Задать домен, разные случайные пароль базы и ключ подписи (`openssl rand -hex 32`), настройки Telegram. Защитить `.env`: `chmod 600 .env`.
3. Выполнить `sh ops/deploy.sh`. Скрипт собирает образ, поднимает БД, отдельно применяет миграции и запускает приложение с Caddy. Caddy автоматически получает TLS-сертификат.
4. Проверить `https://ВАШ-ДОМЕН/health`, вход через браузер и Mini App, создание компании и приглашение друга.

Caddy получает фиксированный внутренний адрес `172.28.44.2`; только этот адрес добавлен в доверенные прокси ASP.NET Core. Динамический диапазон сети отделён от него. При конфликте подсети изменить её и `Proxy__Address` согласованно. HTTPS обязателен для production-cookie. Нельзя добавлять `X-Frame-Options: DENY`: Telegram Web открывает Mini App во фрейме.

Ключи Data Protection сохраняются в отдельном Docker volume с правами непривилегированного пользователя. Не удалять volume `keys` при обычных обновлениях. API и auth-ответы имеют `Cache-Control: no-store`; cookie-запросы на изменение требуют CSRF-токен. Вход ограничен по частоте. OpenAPI доступен авторизованному пользователю по `/openapi/v1.json`.

Перед обновлением сделать резервную копию. Миграции не выполняются web-процессом в Production. Для отката приложения использовать предыдущий Docker-образ; перед несовместимым изменением схемы остановить запись и подготовить восстановление базы. Один VPS не обеспечивает высокую доступность.

## Резервные копии

Настроить отдельное от VPS S3-совместимое хранилище и переменные `S3_*`, `AWS_*` в `.env`. Дать доступ только к выделенному бакету/префиксу. Провайдер должен поддерживать HTTPS и AWS CLI.

```sh
docker compose build backup
docker compose run --rm backup
```

Скрипт делает `pg_dump --format=custom`, отправляет в `darim/daily/` и после успешной отправки удаляет копии этого префикса старше 14 дней. Данные временно хранятся только в контейнере. Предельная потеря при ежедневном расписании — до 24 часов. Настроить уведомление о неуспехе systemd-сервиса средствами мониторинга сервера.

Для ежедневного запуска скопировать `ops/darim-backup.service` и `.timer` в `/etc/systemd/system`, проверить `WorkingDirectory`, затем выполнить `systemctl daemon-reload` и `systemctl enable --now darim-backup.timer`. Проверить журнал первой копии. Для восстановления скачать нужный `.dump`, остановить приложение и выполнить:

```sh
docker compose stop app
sh ops/restore.sh /путь/к/копии.dump
docker compose up -d app
```

Восстановление перезаписывает базу. Сначала регулярно репетировать его в отдельной базе, проверяя желания и пользователей. Секреты и конфигурацию `.env` хранить отдельно в менеджере секретов; бэкап PostgreSQL их не включает.

## Проверки

```sh
dotnet test Wishlist.slnx
python3 -m unittest discover -s tests/ops -v
npm ci
npx playwright install chromium
# PostgreSQL из compose.dev.yaml должен работать
npm run test:e2e
dotnet publish src/Wishlist.Server -c Release -o artifacts/publish
# Проверка собранной и оптимизированной версии:
DARIM_PUBLISHED_TEST=1 npm run test:e2e
```

xUnit запускает временную PostgreSQL 18 через Testcontainers и применяет настоящие миграции; Docker обязателен. Проверяются гонки, приватность, HMAC, сессии, CSRF, изоляция компаний, приглашения и уведомления. bUnit проверяет отображение карточек и обновление состава компании без перезагрузки. Playwright проверяет рабочие сценарии и адаптивность. При использовании системного Chromium задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium`.

CI выполняет .NET-тесты, проверки backup-скрипта, release-publish и браузерные тесты опубликованной сборки. Снимки браузера сохраняются в `artifacts/`, трассировки ошибок — в `test-results/`.
