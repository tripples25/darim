# Darim: backend и отдельный frontend

Darim развивается как приложение из двух репозиториев:

- Этот репозиторий: https://github.com/tripples25/darim — ASP.NET Core API, бизнес-логика, авторизация, PostgreSQL, миграции и инфраструктура.
- https://github.com/sharphurt/darim-frontend — основной развиваемый интерфейс на React/Vite; локально обычно `../darim-frontend`.

## Направление разработки

От Razor/Blazor-фронтенда отказываемся. Новые экраны и изменения пользовательского интерфейса реализуй в `darim-frontend`. `src/Wishlist.Client` — прежний Blazor-интерфейс, сохраняемый на время перехода. Не удаляй его и связанные серверные маршруты в рамках несвязанной задачи: завершение миграции требует отдельной проверки и задачи.

## Работа с двумя репозиториями

- Перед задачей, затрагивающей пользовательский сценарий, прочитай `AGENTS.md` второго репозитория и проверь соответствующие серверные контракты и React-код.
- Источник истины для API — серверные endpoints и `src/Wishlist.Contracts`. При изменении запросов, ответов, авторизации, CSRF или ошибок проверь потребителей в React и согласуй обе стороны.
- Не переноси бизнес-правила и защиту приватности только в интерфейс: сервер обязан обеспечивать их независимо от клиента.
- Для worktree ищи соседний репозиторий по фактическому пути; если его нет рядом, используй основной checkout (на этом компьютере `F:/Playground/darim-frontend`). Не клонируй и не переключай чужие ветки автоматически.
- Это отдельные Git-репозитории: проверяй состояние каждого, делай отдельные коммиты и PR, указывай связанные изменения и порядок выкладки.
- Проверяй изменённую сторону её штатными проверками; для сквозного изменения проверяй обе. Явно сообщай, если вторую сторону или интеграцию проверить не удалось.

Локально сервер запускается по README на `http://127.0.0.1:5080`; Vite проксирует `/api` и `/auth` на этот адрес. Прокси разработки не гарантирует такую же маршрутизацию в production; настройки выкладки проверяй отдельно.
